## `openclaw-proton-pass`

The management CLI, built with `@effect/cli`.

```bash
openclaw-proton-pass --help
openclaw-proton-pass setup
openclaw-proton-pass doctor
```

### `setup`

Prepares the configuration directory. Safe to re-run.

<Steps>
  <Step title="Creates the directory">
    `~/.config/proton-pass-cli`, mode `0700`.
  </Step>
  <Step title="Seeds the configuration">
    `openclaw-secret-map.json` and `openclaw-mcp-proxy.json`, mode `0600`, from
    worked Context7 examples. **An existing file is never overwritten** - the
    secret map is the one piece of state a re-run must not disturb.
  </Step>
  <Step title="Writes the systemd unit">
    `~/.config/systemd/user/openclaw-mcp-auth-proxy.service`, with this
    install's Node binary and proxy entry point resolved. This one *is*
    rewritten on every run.
  </Step>
  <Step title="Prints what to do next">
    The two commands that create the agent token, which `setup` cannot do for
    you because it requires your Proton Pass session.
  </Step>
</Steps>

### `doctor`

Reports what is installed, configured and missing. **Read-only** - it never
creates or repairs anything, so it is safe against a production host.

```
  ok    pass-cli at /home/you/.local/bin/pass-cli
  ok    secret map /home/you/.config/proton-pass-cli/openclaw-secret-map.json
  MISS  agent token /home/you/.config/proton-pass-cli/openclaw-agent-pat - create with: pass-cli agent create openclaw-gateway --expiration 1y --vault OpenClaw
  ok    proxy routes /home/you/.config/proton-pass-cli/openclaw-mcp-proxy.json
  ok    session directory /home/you/.local/state/openclaw-protonpass
```

A failing check is reported and counted; the command still exits successfully,
because "this host is not fully configured" is a report, not a crash.

## `openclaw-protonpass-resolver`

The OpenClaw `exec` secret provider. Reads one JSON request on stdin, writes one
JSON response on stdout, exits.

```bash
echo '{"protocolVersion":1,"ids":["CONTEXT7_API_KEY"]}' | openclaw-protonpass-resolver
```

Not normally invoked by hand - OpenClaw runs it. The [protocol
reference](/reference/protocol) documents the contract.

<Warning>
**stdout is the protocol.** Every log line from every component goes to stderr,
because a single log line on stdout would corrupt the response the Gateway is
parsing.
</Warning>

## `openclaw-pass-run`

Launches a command with `pass://` environment references resolved.

```bash
openclaw-pass-run <command> [args...]
openclaw-pass-run -- <command> [args...]
```

The optional `--` mirrors `pass-cli run`. Every environment variable whose value
begins `pass://` is resolved; everything else is passed through. The child's
stdio is this process's stdio, and its exit code becomes the exit code.

```bash
CONTEXT7_API_KEY="pass://OpenClaw/context7.com/API Key" \
  openclaw-pass-run -- npx -y @upstash/context7-mcp
```

## `openclaw-mcp-auth-proxy`

A loopback HTTP hop that attaches a credential header to requests bound for a
remote MCP server. Takes no arguments; everything comes from
`openclaw-mcp-proxy.json`.

```bash
openclaw-mcp-auth-proxy
```

Exits at startup if the route file is missing, unparseable, has no routes, or
names a non-loopback listen address.

service →](/guides/running-as-a-service)

## Where they come from

<CodeGroup>
```bash Plugin
openclaw plugins install clawhub:@resnovas/openclaw-proton-pass
```

```bash npm
npm install -g @resnovas/openclaw-proton-pass
```

```bash Release archive
# openclaw-proton-pass-bin-<version>.zip - four self-contained bundles,
# runnable with node, no install step and no node_modules.
```

```bash Source
git clone https://github.com/Resnovas/openclaw-proton-pass.git
cd openclaw-proton-pass
pnpm install && pnpm build
node apps/cli/dist/main.js setup
```
</CodeGroup>

Installed as a plugin, the manifest declares the secret provider through
`secretProviderIntegrations`, so installing registers the `protonpass` provider
and removing the plugin revokes it - rather than leaving a hardcoded `command`
path in `openclaw.json` that outlives the thing it points at.
