Every path has a default and an override, so a non-default install prefix or a
relocated home needs no code change. Discovery happens once, in one place, so
the four binaries cannot disagree about where the secret map lives.

The directory is created at mode `0700` and the two seeded files at `0600`.

### `openclaw-secret-map.json`

The only file that records a vault location.

```json
{
  "CONTEXT7_API_KEY": "pass://OpenClaw/context7.com/API Key",
  "CONTEXT7_MCP_AUTHORIZATION": {
    "ref": "pass://OpenClaw/context7.com/API Key",
    "prefix": "Bearer ",
    "suffix": ""
  }
}
```

<ResponseField name="<id>" type="string | object" required>
  A bare `pass://` reference, or an object carrying decoration.
</ResponseField>

<Expandable title="the decorated form">
  <ResponseField name="ref" type="string" required>
    A `pass://` reference. Must begin `pass://`.
  </ResponseField>
  <ResponseField name="prefix" type="string" default='""'>
    Prepended to the resolved value.
  </ResponseField>
  <ResponseField name="suffix" type="string" default='""'>
    Appended to the resolved value.
  </ResponseField>
</Expandable>

An id must be at least one character. See [ids, references and
values](/concepts/ids-references-values) for why the two forms exist.

### `openclaw-agent-pat`

The Proton Pass agent token, as a single line. Mode `0600`. Created by you, not
by `setup`:

```bash
pass-cli agent create openclaw-gateway --expiration 1y --vault OpenClaw
install -m 0600 /dev/stdin ~/.config/proton-pass-cli/openclaw-agent-pat <<< '<token>'
```

### `openclaw-mcp-proxy.json`

```json
{
  "listen": "127.0.0.1:18890",
  "routes": {
    "/context7": {
      "upstream": "https://mcp.context7.com/mcp",
      "header": "Authorization",
      "secretId": "CONTEXT7_MCP_AUTHORIZATION",
      "timeoutSeconds": 120
    }
  }
}
```

<ResponseField name="listen" type="string" default="127.0.0.1:18890">
  Host and port. Loopback only — `127.0.0.1`, `::1` or `localhost`. Anything
  else is rejected when the file loads.
</ResponseField>

<ResponseField name="routes" type="object" required>
  Path to route. At least one, or the proxy refuses to start.
</ResponseField>

<Expandable title="a route">
  <ResponseField name="upstream" type="string" required>
    The real MCP server. Must begin `http`.
  </ResponseField>
  <ResponseField name="secretId" type="string" required>
    An id from the secret map.
  </ResponseField>
  <ResponseField name="header" type="string" default="Authorization">
    The header the credential is attached to.
  </ResponseField>
  <ResponseField name="timeoutSeconds" type="number" default="120">
    Must be positive.
  </ResponseField>
</Expandable>

## Environment variables

### Paths

| Variable | Default |
| --- | --- |
| `OPENCLAW_PROTONPASS_CONFIG_DIR` | `$XDG_CONFIG_HOME/proton-pass-cli`, else `~/.config/proton-pass-cli` |
| `OPENCLAW_PROTONPASS_SECRET_MAP` | `<config dir>/openclaw-secret-map.json` |
| `OPENCLAW_PROTONPASS_AGENT_PAT` | `<config dir>/openclaw-agent-pat` |
| `OPENCLAW_MCP_PROXY_CONFIG` | `<config dir>/openclaw-mcp-proxy.json` |
| `OPENCLAW_PROTONPASS_SESSION_DIR` | `$XDG_STATE_HOME/openclaw-protonpass`, else `~/.local/state/openclaw-protonpass` |
| `PASS_CLI` | found on `PATH`, then `~/.local/bin`, `/usr/local/bin`, `/usr/bin` |

<Note>
A variable exported as the empty string is treated as unset. Taking it
literally would point the resolver at the filesystem root, and an empty export
is a common accident in service units.
</Note>

### Behaviour

| Variable | Default | Effect |
| --- | --- | --- |
| `OPENCLAW_PROTONPASS_TIMEOUT_MS` | `60000` | How long any single `pass-cli` call may take before it is abandoned |

### Telemetry

| Variable | Default | Effect |
| --- | --- | --- |
| `OPENCLAW_PROTONPASS_TELEMETRY` | `true` | Set `false` to send nothing at all |
| `OPENCLAW_PROTONPASS_POSTHOG_KEY` | the project's own key | Point a fork at its own project; the empty string keeps reporting on while sending nowhere |
| `OPENCLAW_PROTONPASS_POSTHOG_HOST` | `https://eu.i.posthog.com` | Ingestion host |
| `OPENCLAW_PROTONPASS_SERVICE_NAME` | `openclaw-proton-pass` | Service name on traces, metrics and logs |
| `OPENCLAW_PROTONPASS_ENVIRONMENT` | `production` | Deployment environment reported alongside them |

[What is reported, and why a secret cannot be →](/security/telemetry)

## OpenClaw's own configuration

Registering the provider by hand, when not installed as a plugin:

```bash
openclaw config set secrets.providers.protonpass.source exec
openclaw config set secrets.providers.protonpass.command "$(command -v openclaw-protonpass-resolver)"
openclaw config set secrets.providers.protonpass.jsonOnly true
openclaw config set secrets.providers.protonpass.timeoutMs 60000
```

`timeoutMs` should be at least `OPENCLAW_PROTONPASS_TIMEOUT_MS`, or the Gateway
will give up while the resolver is still waiting on the vault.

## Verifying what was discovered

`doctor` prints the resolved paths rather than the defaults, which is the
quickest way to find out that an override is not doing what you expected:

```bash
openclaw-proton-pass doctor
```
