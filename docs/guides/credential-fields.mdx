---
title: "Credential fields"
description: "Point a model provider's API key, or any other SecretRef field, at a secret in your Proton Pass vault."
---

This is the path to prefer. The field holds a reference, OpenClaw asks the
provider for the value, and nothing is written anywhere.

## Prerequisites

The [quickstart](/quickstart) through step 4: an agent token, an entry in the
secret map, and the provider registered.

## Add the entry

```json title="~/.config/proton-pass-cli/openclaw-secret-map.json"
{
  "CONTEXT7_API_KEY": "pass://OpenClaw/context7.com/API Key"
}
```

## Point the field at it

```bash
openclaw config set models.providers.openai.apiKey \
  --ref-provider protonpass --ref-source exec --ref-id CONTEXT7_API_KEY
```

The field now holds a reference rather than a value:

```json title="openclaw.json"
{
  "models": {
    "providers": {
      "openai": {
        "apiKey": { "$secretRef": { "provider": "protonpass", "source": "exec", "id": "CONTEXT7_API_KEY" } }
      }
    }
  }
}
```

<Note>
The exact shape OpenClaw writes is its own; what matters is that no value
appears. If you see the credential itself in `openclaw.json`, the `--ref-*`
flags did not take effect.
</Note>

## Confirm it resolves

```bash
openclaw-proton-pass doctor
```

To exercise the protocol directly:

```bash
echo '{"protocolVersion":1,"ids":["CONTEXT7_API_KEY"]}' \
  | openclaw-protonpass-resolver
```

```json Response
{ "protocolVersion": 1, "values": { "CONTEXT7_API_KEY": "..." } }
```

<Warning>
That prints the value to your terminal. Use it once to confirm the path, then
rotate the item if the terminal is not private.
</Warning>

## Several fields, one vault entry

Nothing stops two ids pointing at the same reference. That is the intended way
to serve a bare field and a decorated header from one vault item - see
[ids, references and values](/concepts/ids-references-values).

## When it does not work

| Symptom | Likely cause |
| --- | --- |
| `"errors": { "...": "NOT_FOUND" }` | The id is absent from the map, or the reference resolves to nothing |
| `"error": "..."` at the top level | The map is unreadable, or no session could be established |
| The Gateway never calls the provider | The provider is not registered, or the Gateway was not restarted |

[Troubleshooting](/troubleshooting) goes through each of these.
